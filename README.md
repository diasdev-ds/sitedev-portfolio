# Портфолио SiteDev — автоматизация бизнеса и AI-интеграции

Четыре проекта, упорядочены от самого сильного. Все запускаются локально,
ключи и доступы в репозитории не публикуются — в каждом проекте есть `.env.example`.

| Проект | Что решает | Стек | Что показать |
|---|---|---|---|
| [chat-audit](https://github.com/diasdev-ds/chat-audit) | Считает, сколько горячих лидов и денег теряет магазин из-за медленных ответов в мессенджерах | Python (stdlib), SQLite, HTML-дашборд | `report.html` |
| [order5-ai](https://github.com/diasdev-ds/order5-ai) | Сводит Telegram, почту и Bitrix24 в одну базу и выдаёт руководителю AI-дайджест с приоритетами | Python, PostgreSQL, Groq/Llama, Telegram Bot API | Живая демонстрация бота |
| [demo-scan-ai](https://github.com/diasdev-ds/demo-scan-ai) | Распознаёт сканы накладных и счетов, выгружает данные в 1С и Excel | Python, GPT-4 Vision, PyMuPDF, openpyxl | `результат_*.xlsx` |
| [integrations-1c](https://github.com/diasdev-ds/integrations-1c) | Учебный стенд интеграции «банк → 1С»: загрузка выписки и сопоставление платежей | Python/Flask (мок банка), 1С:BSL | Код внешней обработки |

## 1. [chat-audit](https://github.com/diasdev-ds/chat-audit) — аудит переписки

**Задача клиента.** B2C-магазин техники, Алматы. Менеджеры не успевают отвечать
в мессенджерах и Instagram, горячие заявки теряются. Нужно показать на данных,
сколько именно теряется.

**Что делает.** На входе — выгрузка переписки WhatsApp (`.txt`), CSV или JSON.
На выходе — HTML-дашборд: сколько диалогов остались без ответа, какое время
реакции, сколько денег упущено и в какие часы проседает отдел.

**Продуктовое решение:** AI здесь — пассивный наблюдатель. Он дёргает менеджера,
а не отвечает покупателю. Это требование заказчика, в коде зафиксировано.

**Персональные данные.** Телефоны и email маскируются при загрузке, имя клиента
не сохраняется. Обработка полностью локальная.

**Запуск** (зависимостей нет, Python 3.9+):
```bash
cd chat-audit
python3 demo.py --synthetic --open          # демо на 200 синтетических диалогах
python3 demo.py --input путь/к/chat.txt     # на реальной выгрузке
```

Результат на синтетике: 200 диалогов, ~63 пропущенных горячих лида, ~21,7 млн ₸
упущенной выручки. Смена ниши и среднего чека — один файл `config.py`.

## 2. [order5-ai](https://github.com/diasdev-ds/order5-ai) — AI-мониторинг коммуникаций

**Задача клиента.** Компания, 7 филиалов, ~400 сотрудников, 7 Telegram-групп,
корпоративная почта и Bitrix24. Руководитель тонет в трёх потоках информации.

**Что делает.** Все источники пишут в одну таблицу PostgreSQL. Поверх неё AI
строит дайджест с приоритетами, из критичных пунктов автоматически создаются
задачи в Bitrix24. Ежедневная отправка по расписанию.

**Ключевой принцип:** сотрудникам не нужно ничего устанавливать. Они работают
в своих группах как раньше. Команды доступны только руководителям из белого списка.

| Команда | Что делает |
|---|---|
| `/digest` | AI-дайджест по всем источникам с приоритетами |
| `/search <текст>` | Поиск по всем источникам сразу |
| `/client <имя>` | Карточка клиента |
| `/task <описание>` | Создаёт задачу в Bitrix24 |

**Архитектура.** Модульная: каждый источник — отдельный коннектор
(`integrations/mail.py`, `integrations/bitrix.py`), AI-провайдер заменяется
без переделки системы. Защита от дублей по `source_id`.

**Запуск:**
```bash
cd order5-ai
cp .env.example .env         # заполнить своими доступами
docker compose up -d         # PostgreSQL 16 + pgvector
pip install -r requirements.txt
python db/init.py && python bot/collector.py
```

## 3. [demo-scan-ai](https://github.com/diasdev-ds/demo-scan-ai) — распознавание документов в 1С

**Задача.** Бухгалтерия вручную вбивает данные со сканов накладных и счетов.

**Что делает.** Принимает PDF и фото документов, распознаёт через GPT-4 Vision,
извлекает номер, дату, контрагента, БИН/ИИН и позиции таблицы, выгружает в Excel
и отправляет в 1С через REST. Приём документов — через Telegram-бота.

Поддержаны документы на русском и казахском. В репозитории лежит пример результата —
`результат_20260621_154400.xlsx`.

| Файл | Назначение |
|---|---|
| `process_docs.py` | Распознавание через GPT-4 Vision, выгрузка в Excel |
| `extractor.py` | Разбор PDF постранично |
| `sender_1c.py` | Отправка в 1С |
| `mock_1c_server.py` | Мок 1С для отладки без боевой базы |
| `telegram_bot.py` | Приём документов от пользователя |

## 4. [integrations-1c](https://github.com/diasdev-ds/integrations-1c) — стенд «банк → 1С»

Учебно-демонстрационный стенд загрузки банковской выписки в 1С. Мок банка на
Flask отдаёт намеренно «грязную» выписку: ИНН в разных форматах, 10 знаков у ООО
и 12 у ИП, платежи без ИНН в назначении, похожие названия контрагентов с разными
ИНН, дубли платежей и 20% сбоев сервера.

Это тренажёр на реальные грабли интеграций: разбор назначения платежа,
идемпотентность, обработка отказов внешнего сервиса.

**Архитектурный подход** (переносится на Kaspi, WB, Ozon):
внешняя обработка 1С собирает все ИНН в массив и делает **один запрос**
`ГДЕ Контрагенты.ИНН В (&МассивИНН)` вместо запроса в цикле, сопоставление идёт
в памяти через `Соответствие`. Доработки — через расширения, без правки типовой
конфигурации, чтобы обновление у клиента ничего не ломало.

```bash
python3 mock_bank/bank_server.py   # порт 8080
```
